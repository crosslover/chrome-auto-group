# 不持久化标签页状态的自动换组

状态：已接受

扩展不持久化规则、标签页历史或分组来源。网站识别包含一份代码内置的常见网站名称标签表，例如 `google`、`bing`、`youtube`；它不维护 hostname 到网站名称的映射，也不把 `youtu.be` 特别映射成 `youtube`。hostname 转成小写并按 `.` 分割，排除 `www` 和公共后缀标签后，先检查注册域名主体是否命中内置表；未命中时再检查其他 hostname 标签，若有多个命中则选择离注册域名主体最近的标签；完全未命中时使用注册域名主体作为默认标识。因此 `www.google.com` 得到 `google`，`notgoogle.com` 得到 `notgoogle`，`google.example.com` 得到 `google`，`youtu.be` 得到 `youtu`。公共后缀判断使用代码内的小型常见多段后缀表。不提供用户规则编辑或联网更新。新建且未分组的普通网页标签页按当前网站标识加入对应分组；已分组标签页发生网址变化时，仅当当前分组标题恰好是代码规则识别出的网站标识，才视为自动分组并换入新网站的分组。其他分组视为用户手动安排并保持不动。分组按浏览器窗口复用，使用小写网站标识作为标题。

这一决定避免启动时恢复或扫描标签状态，并让常规手动分组在跳转后保持不变。由于 Chrome 没有可供本方案使用的持久分组来源标记，用户手动创建与网站标识同名的组无法和扩展创建的组区分；该极少数歧义按标题规则处理并予以接受。已有标签页只在用户显式触发“整理当前窗口”时整理，且只处理未分组的普通网页标签页。

2026-10-17 经用户确认，允许仅将新建标签页等待首次普通网页地址的待处理标记（标签 ID）暂存在 `chrome.storage.session`。这是对原先“不保存标签 ID”约束的有限修订：标记只驻留浏览器内存，不写入磁盘或同步，在分组、手动入组或关闭标签页后删除，浏览器重启或扩展重新加载时自动清除；不保存网址、历史、组 ID 或分组来源。这样空白新标签页即使等到 MV3 worker 休眠后再输入地址，仍能自动分组，同时无需启动扫描或处理已有未分组网页。
