# 领域文档

工程技能在探索代码库时，应按以下规则读取领域文档。

## 开始探索前

- 读取仓库根目录的 `GLOSSARY.md`；如果存在 `GLOSSARY-MAP.md`，则按其中的映射读取与当前主题相关的词汇表
- 阅读与当前工作区域相关的 `docs/adr/` 中的架构决策记录
- 如果存在多上下文结构，也检查 `src/<上下文>/docs/adr/` 中的上下文级决策

如果这些文件不存在，继续工作即可；不要专门指出文件缺失，也不要提前建议创建。只有在术语或决策实际得到确认时，才通过 `/domain-modeling` 创建相应文档。

## 文件布局

本项目采用单上下文布局：

    /
    ├── GLOSSARY.md
    ├── docs/adr/
    └── src/

## 使用词汇表中的术语

在任务标题、重构建议、假设或测试名称中提到领域概念时，使用 `GLOSSARY.md` 定义的术语。不要改用词汇表明确避免的同义词。

如果需要的概念尚未收录，先判断是否引入了项目并未使用的新说法，或确实存在需要通过 `/domain-modeling` 补充的术语。

## 指出与架构决策的冲突

如果输出与现有 ADR 冲突，应明确指出冲突，而不是默默覆盖。例如：

> 这与 ADR-0007 的决定冲突；不过，基于……，可以考虑重新讨论该决定。
