# 01: 新标签页按网站标识自动分组

**What to build:** 普通网页标签页打开后自动进入当前窗口内以小写网站标识命名的标签组；相同网站复用已有组，未知网站也能按默认规则整理。

**Blocked by:** None (can start immediately)

**Status:** resolved

## 实施记录

- 使用 pnpm 管理依赖与执行检查。
- 沿用已确认的 Chrome 扩展行为测试 seam：真实加载扩展，通过标签页创建、导航驱动行为，并检查原生标签组；不增加内部识别函数测试。
- 2026-10-17 用户确认允许仅用 `chrome.storage.session` 暂存待处理标签 ID，覆盖空白页等待期间 worker 休眠后的首次导航；约束已同步到规格与 ADR-0001。

- [x] 新建普通 HTTP/HTTPS 标签页后，根据 hostname 识别网站标识，并在当前窗口创建或复用对应标签组。
- [x] 内置表只包含网站名称标签，例如 `google`、`bing`、`youtube`；按完整 hostname 标签匹配，不做任意子串匹配，也不维护域名到品牌的映射。
- [x] 按 ADR 的优先级处理多标签命中，并在没有内置名称命中时以注册域名主体作为默认标识；覆盖 `notgoogle.com`、`google.example.com` 和 `youtu.be` 等约定示例。
- [x] 忽略 `www` 与公共后缀标签；公共后缀处理覆盖常见多段后缀。
- [x] 跳过 Chrome 内部页面、扩展页面、本地文件等非普通网页地址。
- [x] 同一窗口复用同名组，不同窗口各自建立组。
- [x] 后台处理由标签页事件触发，不枚举或重整启动时已有的全部标签页。
- [x] 不持久化规则、偏好、标签页状态或分组来源，不进行云同步或网络请求；仅允许 session 内存待处理标签 ID 标记，按规格与 ADR 清除。
- [x] 空白新标签页等待到 worker 休眠后，首次进入普通网页仍会自动分组。
- [x] 建立 Chrome 扩展行为测试 seam，验证标签页创建后的可见分组结果和窗口隔离。

## Answer

- 完成 Manifest V3 扩展，运行文件位于 [extension/](../../../extension/)，仅使用 `tabs`、`tabGroups` 与经用户确认的 `storage.session`，最低支持 Chrome 102。
- 网站标识规则、并发组复用及窗口隔离均通过原生 Chrome 标签组行为验证；无需启动扫描，不保存网址、历史或分组来源。
- `pnpm typecheck` 通过；`pnpm test` 全套 14 项通过，涵盖真实浏览器会话恢复与空白页跨 worker 休眠后的首次导航。
- 生命周期回归测试已验证旧实现失败、session 修复后通过；时序修正后该场景连续通过 5 次，会话恢复场景连续通过 3 次。
- `code-review` 两轴复审：Standards 0 项、Spec 0 项未解决发现。
- 开发与验证命令见 [README](../../../README.md)。票据 02 已解除依赖；跨站导航换组、工具栏整理与发布包留待后续票据实现。
